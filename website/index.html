The approach

Production readiness is a system, not a checkbox.

Fieldbook keeps the difficult parts visible before launch: what applies, what was actually verified, who owns the risk, what remains unresolved, and what evidence supports the decision.

01 / Define

Make requirements explicit

Document behavior, privacy constraints, release controls, ownership and acceptable exceptions while changes are still inexpensive.

02 / Verify

Attach actual evidence

Connect implementation, tests, observations and review records to the requirement instead of relying on assumptions or screenshots alone.

03 / Release

Keep authority accountable

Surface blockers and unresolved risks clearly. A tool can report evidence, but it cannot take responsibility for the release.

Release workflow

From applicability to sign-off.

01 · SCOPE

Define applicability

Identify routes, data, providers, environments and controls that actually apply.

02 · CONTRACT

Set the behavior

Specify page and component states, authority boundaries, accessibility and failure behavior.

03 · EVIDENCE

Verify the implementation

Record tests, release context, owners, exceptions and concrete supporting evidence.

04 · DECIDE

Review blockers

Keep security, privacy, recovery and truth-critical failures from being hidden by a score.

The toolkit

Operational material, not decorative documentation.

The repository combines reusable records, machine-readable controls, bounded agent instructions, schema validation, release tooling, and a deliberately fictional reference product.

Get started

Adopt only what applies.

Install Fieldbook from npm, run it in your project, and complete the human review record before treating any result as release evidence.

# run without a global install
npx fieldbook init
npx fieldbook check
npx fieldbook report --json

# optional security evidence
npx codevet-cli scan --json codevet-report.json
npx fieldbook codevet codevet-report.json --attach

Current boundary

Advisory, by design.

The CLI does not run a penetration test, prove legal compliance, or certify a production release. The authoritative Edition 1 controls remain in agent/controls.yaml.
