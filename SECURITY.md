# Security policy

## Reporting

Do not open a public issue containing a vulnerability, secret, personal data, exploit payload, or production evidence. Contact the repository owner through the private security-reporting channel configured on the hosting platform. A public email address is intentionally not invented in this release.

Include the affected version, file or control, impact, safe reproduction conditions, and redacted evidence. Do not access data or systems beyond the minimum authorized scope.

## Scope

The validator checks repository structure, selected schema rules, links, placeholders, examples, control consistency, and release checksums. It is not a malware scanner, secret-management system, penetration test, legal review, accessibility audit, or proof that a consuming website is secure.

## Supported release

Security fixes target the latest published companion release. Older versions may receive documentation-only corrections at the maintainer's discretion.
